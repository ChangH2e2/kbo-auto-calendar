# KBO GameDay 디자인 브리프

## 1. 디자인 방향

스포츠 중계 화면처럼 과장되거나 팀 컬러로 화면 전체를 채우지 않는다. **차분한 일정 도구 위에 경기의 긴장감이 얹힌 형태**를 목표로 한다. 정보 밀도는 높지만 카드 간 위계가 명확해야 한다.

키워드: `calm sports utility`, `editorial scoreboard`, `confident`, `compact`, `Korean mobile-first`

## 2. 시각 언어

- 기본 배경: 따뜻한 아이보리 또는 아주 옅은 회색
- 기본 텍스트: 짙은 네이비
- 포인트: 깊은 코발트 블루
- 상태색:
  - 예매 임박: 앰버
  - 진행 중: 선명한 레드
  - 종료/일반: 네이비·회색
  - 취소: 저채도 레드
- 팀 컬러는 작은 점, 얇은 테두리, 로고 배경 등에 제한적으로 사용
- 모서리는 지나치게 둥글지 않은 12~16px
- 그림자보다 선과 면의 대비로 계층 표현

## 3. 타이포그래피

- 한글 본문: Pretendard 계열
- 점수·시간·카운트다운: tabular 숫자를 지원하는 굵은 산세리프
- 화면 제목 24~30px, 주요 점수 36~48px, 본문 14~16px
- 작은 텍스트를 11px 미만으로 만들지 않음

## 4. 모바일 홈 화면

### 상단

- `KBO GameDay` 워드마크
- 응원팀 전환 버튼
- 설정 아이콘

### 다음 경기 히어로 카드

- `다음 경기` 라벨과 경기일까지 남은 날짜
- 원정팀과 홈팀을 좌우로 배치
- 중앙에 경기 시각
- 장소 및 중계/선발 정보
- 홈 경기라면 예매 상태 패널과 공식 예매 버튼

### 오늘의 경기

- 세로 리스트
- 시간, 두 팀, 점수/상태를 한 줄 위계로 표현
- 진행 중인 경기만 라이브 강조

### 하단 내비게이션

- 오늘
- 일정
- 설정

## 5. 데스크톱 일정 화면

- 좌측 얇은 사이드바: 응원팀, 오늘, 일정, 설정
- 상단: 월 제목, 이전/오늘/다음, 팀 및 홈/원정 필터
- 본문: 7열 월간 캘린더
- 한 날짜에 여러 경기가 있을 수 있는 카드 구조
- 오른쪽 보조 패널: 선택한 날짜의 경기 상세와 예매 상태
- 달력 칸에서 모든 선수 기록을 보여주지 않고 상태·팀·시간·점수만 표시

## 6. 경기 상세 모바일 화면

- 상단 고정 뒤로가기와 공유
- 상태 라벨, 날짜, 구장
- 팀 이름과 큰 점수
- 예정 경기는 예매 CTA, 종료 경기는 최종 상태
- 스코어보드는 가로 스크롤 가능하되 팀명과 합계 열을 고정하는 방향
- 탭: 개요 / 타자 / 투수
- 데이터 갱신 시각과 출처는 화면 하단에 배치

## 7. 주요 컴포넌트

- `GameStatusBadge`
- `NextGameHero`
- `TicketCountdown`
- `GameListRow`
- `MonthGameChip`
- `ScoreboardTable`
- `PlayerStatsTable`
- `DataFreshnessNotice`
- `TeamPicker`

## 8. 접근성 기준

- 텍스트 대비 WCAG AA 이상
- 색상만으로 상태를 전달하지 않고 아이콘·문구 병행
- 모든 터치 대상 최소 44×44px
- 라이브 점수 자동 갱신은 스크린리더에 과도하게 반복 통지하지 않음
- 모션 감소 설정 존중
- 팀 로고가 없어도 팀명이 항상 표시됨

## 9. 목업 제작 기준

### 목업 A — 모바일 오늘

- 390×844 비율의 스마트폰 화면
- LG를 응원팀으로 설정한 예시
- 다음 경기 및 `예매 02:14:32 전` 상태
- 오늘의 경기 3개
- 실서비스 수준의 한국어 UI

### 목업 B — 데스크톱 월간 일정

- 1440×1000 데스크톱 화면
- 9월 월간 캘린더와 우측 선택 날짜 패널
- 경기 있음/없음/종료/예정/취소 상태가 섞인 예시
- 모바일 목업과 동일한 디자인 시스템

### 목업 C — 모바일 종료 경기 상세

- 390×844 비율
- 최종 점수, 이닝 스코어, 타자·투수 탭
- 촘촘하지만 읽기 쉬운 기록 화면
- 출처와 갱신 시각 표시

## 10. 피해야 할 표현

- 지나친 그라디언트와 네온 효과
- 모든 요소를 둥근 카드로 분리하는 대시보드 스타일
- 장식용 야구공·배트 일러스트 남용
- 10px 이하의 읽기 어려운 텍스트
- 모바일 월간 칸 안에 경기 세부 정보를 과도하게 압축
- 공식 KBO 또는 구단 로고를 허가 없이 정확히 복제

## 11. Claude 리뷰 후 확정 규칙

### 팀 배치

- 모든 화면에서 **원정팀은 왼쪽, 홈팀은 오른쪽**으로 고정한다.
- 홈팀에는 위치 외에도 `홈` 마이크로 라벨 또는 얇은 세로 바를 표시한다.
- 목록·히어로·캘린더·상세에서 예외를 만들지 않는다.

### 상태 토큰

| 상태 | 색 | 형태 | 표시 문구 |
| --- | --- | --- | --- |
| 예정 | 중립 회색 | 기본 행, 별도 배지 없음 | 시간만 표시 |
| 예매 임박 | 앰버 | 4px 바 + 티켓 아이콘 | `예매 오픈 D-2` |
| 예매 중 | 코발트 | 채운 배지/활성 CTA | `예매 중` |
| 진행 | 짙은 레드 | 점 + 텍스트, 깜빡임 없음 | `LIVE 7회초` |
| 종료 | 네이비/회색 | 외곽선 | `종료 · 승` 또는 `종료 · 패` |
| 취소 | 저채도 레드 | X 아이콘 + 사선 패턴 | `취소` |
| 연기 | 저채도 앰버 | 점선 테두리 | `연기` |

- 코발트 블루는 링크, 선택, 실제 실행 가능한 CTA에 우선 사용한다.
- 상태는 색상뿐 아니라 형태와 문구로 함께 전달한다.

### 예매 CTA

- `예매까지` 대신 `예매 오픈까지`를 사용한다.
- 카운트다운과 함께 `9월 6일(일) 14:00 오픈`처럼 절대 시각을 병기한다.
- 오픈 전 버튼은 secondary/outline, 예매 중일 때만 primary로 표시한다.

### 데이터와 UI의 계약

- 화면에 표시하는 모든 값은 수집 스키마의 필드와 출처가 있어야 한다.
- 정의되지 않은 `득점 찬스`, 효율 평가 같은 파생 지표와 감상형 문구는 사용하지 않는다.
- 선수 상세 라우트가 없는 동안 선수 행에 아바타나 이동 chevron을 표시하지 않는다.
- 구단 로고 라이선스가 확정되기 전에는 자체 원형 토큰과 한글 약칭을 사용한다.

### 최악 조건 기준

- 데스크톱 월간 셀은 하루 5경기에서 검증한다.
- 셀에는 최대 3경기만 표시하고 초과분은 `+2경기`처럼 요약한다.
- 모바일 기록표는 12회 연장에서도 팀명과 R/H/E가 고정되도록 설계한다.
- 360px 모바일, 더블헤더, 최장 팀명, 취소·연기 상태를 기본 QA fixture에 포함한다.
