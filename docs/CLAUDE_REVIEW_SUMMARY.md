## 총평

시각 완성도와 `차분한 스포츠 유틸리티` 방향은 구현 가능한 수준이다. 다만 세 목업이 홈/원정 배치, 상태색, 정보 근거에 서로 다른 규칙을 사용하고, 하루 5경기·12회 연장·취소·연기처럼 실제 서비스에서 중요한 최악 조건을 검증하지 않았다. 현재 상태로 구현하면 규칙 결정을 개발 단계로 떠넘기게 되므로 P0 항목을 먼저 설계에 고정해야 한다.

## P0 — 구현 전에 해결

1. **목업 시간축 정합성**
   - 다음 경기가 17:00인데 오늘 경기의 다른 17:00 경기가 이미 7회인 예시는 모순이다.
   - 모든 목업에 명시적인 기준 시각을 둔다.
   - 다음 경기가 진행 상태가 되면 히어로는 카운트다운 대신 현재 점수·이닝으로 전환한다.

2. **홈/원정 위치 통일**
   - 원정 왼쪽, 홈 오른쪽으로 모든 화면을 통일한다.
   - 홈 마이크로 라벨을 추가해 위치와 텍스트로 이중 전달한다.

3. **상태 토큰 충돌 제거**
   - 예정은 중립, 라이브는 레드, 종료는 네이비/회색으로 고정한다.
   - 코발트는 선택·링크·활성 CTA에 사용한다.
   - 취소와 연기는 색뿐 아니라 사선/점선과 문구로 구분한다.

4. **데이터가 없는 파생 지표 제거**
   - `득점 찬스 6/12`, `더 효율적이었어요` 등은 현재 수집 모델로 계산할 수 없다.
   - 승리/패전/세이브 투수, 홈런, R/H/E처럼 공식 데이터로 확인 가능한 사실만 사용한다.

5. **구단 마크 법적 리스크 제거**
   - 생성 목업의 L/D/T/E/G/N/SL 마크가 실제 구단 마크와 유사하다.
   - 라이선스 전에는 단색 원형 토큰과 팀명 텍스트로 대체한다.

## P1 — 첫 릴리스 전에 해결

- `예매 오픈까지`와 실제 오픈 일시를 함께 표시한다.
- 예매 전 CTA는 secondary, 실제 예매 중에만 primary로 전환한다.
- 전체 경기 모드에서 하루 5경기를 표시할 캘린더 셀 규칙을 만든다.
- 팀 필터 화면에서는 반복되는 응원팀 이름과 기본 `예정` 배지를 줄인다.
- 데스크톱 우측 패널을 `날짜 → 그날 경기 목록 → 선택 경기` 구조로 바꾼다.
- 종료 경기는 우측 축약 스코어보드에서 전체 상세로 이어지게 한다.
- 모든 데이터 화면에 갱신 시각을 표시하고 30분 지연 시 배너를 띄운다.
- 응원팀 변경과 일정 필터 컨트롤의 역할을 분리한다.
- 12회 연장 시 팀명 왼쪽, R/H/E 오른쪽을 고정하고 이닝만 스크롤한다.
- 존재하지 않는 선수 상세 화면을 암시하는 chevron과 아바타를 제거한다.

## 유지할 요소

- 오늘/일정/설정의 3탭 구조
- 데스크톱의 얇은 사이드바와 이전/오늘/다음 탐색
- 모바일 상세의 이닝 스코어보드, R/H/E, 9회말 X 처리
- 한 행 안에서 시간·양 팀·점수·상태를 읽는 오늘의 경기 목록
- 출처와 마지막 갱신 시각 표시

## 최종 구현 원칙

1. 원정 왼쪽, 홈 오른쪽을 예외 없이 적용한다.
2. 상태는 색·형태·문구로 함께 표현한다.
3. 파랑은 선택·링크·활성 CTA에 예약한다.
4. 팀 컬러는 작은 바·점·테두리로만 사용한다.
5. 표시 값은 반드시 수집 필드와 출처를 가진다.
6. 모든 데이터 화면에서 갱신 시각을 볼 수 있어야 한다.
7. 최상의 예시가 아니라 최악의 밀도로 설계하고 테스트한다.
8. 예매 CTA는 실제 행동 가능 상태에서만 강조한다.
9. 모바일은 주간 목록을 기본으로, 월간은 보조로 둔다.
10. 장식보다 선발·구장·중계·갱신 시각 같은 사실을 우선한다.
