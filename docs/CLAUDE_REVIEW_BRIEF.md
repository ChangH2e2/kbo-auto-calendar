# Claude Design 리뷰 요청서

## 역할

당신은 스포츠 일정·티켓·라이브 스코어 제품 경험을 검토하는 시니어 프로덕트 디자이너다. 첨부한 제품 청사진, 아키텍처, 디자인 브리프와 목업 3종을 서로 교차 검토한다.

## 프로젝트 목표

KBO 야구팬이 응원팀의 다음 경기, 예매 오픈 시점, 전체 일정, 종료 경기 기록을 가장 짧은 동선으로 확인하게 한다. 모바일에서는 오늘과 주간 흐름을 우선하고, 데스크톱에서는 월간 탐색 효율을 높인다.

## 첨부 자료

- `PRODUCT_BLUEPRINT.md`: 사용자, 문제, MVP, 상태 모델, 로드맵
- `ARCHITECTURE.md`: 데이터 수집, Supabase, 읽기 API, 운영 안정성
- `DESIGN_BRIEF.md`: 디자인 원칙, 화면 구성, 접근성
- `mobile-today.png`: 모바일 오늘 화면
- `desktop-calendar.png`: 데스크톱 월간 일정
- `mobile-game-detail.png`: 모바일 종료 경기 상세

## 검토 질문

1. 제품의 핵심 가치와 첫 화면의 정보 위계가 일치하는가?
2. 모바일 오늘 화면에서 다음 경기와 예매 행동이 지나치게 크거나 중복되지 않는가?
3. 데스크톱 월간 화면의 캘린더와 우측 상세 패널 조합이 효율적인가?
4. 종료 경기 상세가 기록 밀도와 읽기 쉬움 사이의 균형을 잡았는가?
5. 예정·예매 임박·예매 중·진행·종료·취소 상태가 색상 외 수단으로 충분히 구분되는가?
6. 응원팀 중심 경험과 전체 리그 탐색이 충돌하지 않는가?
7. 360~390px 모바일과 1440px 데스크톱에서 예상되는 접근성·반응형 문제가 무엇인가?
8. 목업에서 구현 전에 반드시 바꿔야 할 사항은 무엇인가?

## 원하는 답변 형식

1. 한 문단 총평
2. `유지 / 수정 / 제거 / 추가` 표
3. 심각도 순 `P0 / P1 / P2` 문제 목록과 구체적인 수정안
4. 세 화면 각각의 정보 구조 및 시각 디자인 리뷰
5. 개선된 사용자 흐름
6. 구현팀이 바로 사용할 수 있는 최종 디자인 원칙 10개
7. 다음 목업 라운드에서 검증할 질문 5개

칭찬보다 문제 발견을 우선하고, 취향이 아니라 사용자 목표·정보 위계·접근성·구현 가능성을 근거로 판단해 달라.
